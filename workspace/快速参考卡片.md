## 🐍 Python API 速查

```python
from guardian import Guardian, TaskConfig

# 配置
config = TaskConfig(
    max_duration=300,      # 5分钟上限
    max_iterations=3,      # 最多3轮
    quality_threshold=0.85 # 85分算合格
)

# 使用上下文管理器
with Guardian(config, "任务名") as guard:
    while guard.can_continue():
        iter_num = guard.iteration_start()
        
        # 执行任务
        result = do_work()
        
        # 保存检查点
        guard.checkpoint(result)
        
        # 检查质量
        if guard.meets_threshold(result):
            guard.deliver(result, "quality_met")
            break
    
    # 强制交付
    if not guard.state.delivered:
        guard.deliver(result, "max_iterations")
```

## ⚠️ 死循环警示信号

| 信号 | 含义 | 行动 |
|------|------|------|
| 超过5分钟无输出 | 可能陷入循环 | 检查是否可以交付中间结果 |
| 迭代超过3轮 | 优化可能过度 | 评估当前结果是否"足够好" |
| 质量提升<5% | 边际效益递减 | 停止迭代，交付当前版本 |
| 用户询问进度 | 用户感知延迟 | 立即报告状态并询问是否继续 |

## ✅ 最佳实践检查清单

### 任务开始前
- [ ] 定义明确的"完成"标准
- [ ] 设置时间盒（默认5分钟）
- [ ] 设置迭代上限（默认3轮）
- [ ] 确定质量阈值（默认0.8）
- [ ] 准备降级方案

### 任务执行中
- [ ] 每轮迭代后报告进度
- [ ] 每30秒输出状态信息
- [ ] 达到50%时间时评估是否继续
- [ ] 达到80%时间时启动收尾
- [ ] 随时准备交付"当前最佳"

### 任务完成后
- [ ] 记录实际用时vs预估
- [ ] 总结迭代次数是否合理
- [ ] 更新经验库
- [ ] 优化下次的任务边界

## 📊 时间盒参考

| 任务类型 | 建议时间 | 迭代次数 |
|---------|---------|---------|
| 内容生成 | 5-10分钟 | 3轮 |
| 数据分析 | 3-5分钟 | 2轮 |
| 代码生成 | 10-15分钟 | 4轮 |
| 报告撰写 | 8-12分钟 | 3轮 |
| 图片生成 | 2-3分钟 | 2轮 |

## 🎯 质量阈值建议

| 场景 | 阈值 | 说明 |
|------|------|------|
| 快速原型 | 0.6 | 先完成再优化 |
| 标准交付 | 0.8 | 默认推荐 |
| 关键任务 | 0.9 | 需要更多时间 |
| 演示/POC | 0.7 | 展示概念即可 |

## 🔄 迭代策略

```
第1轮: 快速完成 (MVP)
   └─ 目标: 有可交付的成果
   └─ 时间: 40%总时间

第2轮: 核心优化
   └─ 目标: 解决主要问题
   └─ 时间: 35%总时间

第3轮: 精细打磨
   └─ 目标: 提升体验
   └─ 时间: 25%总时间
```

## 🆘 紧急处理

如果已经陷入死循环：

```bash
# 1. 立即中断
Ctrl+C

# 2. 保存当前状态
guardian checkpoint --force

# 3. 评估是否可以交付当前结果
# 如果可以，立即交付
# 如果不可以，启动降级方案

# 4. 复盘原因，更新配置
# - 时间盒是否太短？
# - 迭代次数是否太少？
# - 质量阈值是否太高？
```

## 💡 黄金法则

1. **完成 > 完美** - 80分就交付
2. **可见 > 完美** - 展示进度比追求完美重要
3. **时间到就交** - 不要犹豫

5. **保留改进空间** - 告诉用户这是V1
