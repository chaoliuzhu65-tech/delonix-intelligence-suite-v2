## 一、核心理念

### 核心原则
1. **实时沉淀**：每完成一项工作，立即写入资产库
2. **全员可访问**：所有知识资产放在共享池，任何AI伙伴可读
3. **结构化存储**：统一格式、统一分类、统一检索
4. **可追溯可评价**：每次写入记录作者、时间、状态，方便考核

### vs 旧模式的区别
| 旧模式 | 新模式 |
|--------|--------|
| 各AI本地存储 | 统一共享池 |
| 知识散落各处 | 分类清晰 |
| 难以检索 | 结构化索引 |
| 无考核机制 | 每次写入可追溯 |
| 重复造轮子 | 知识复用率高 |

## 三、每小时汇报机制（强制执行）

### 汇报时机
- **每小时整点**（00分）前必须完成汇报
- 每次完成重要工作后立即补充汇报

### 汇报格式（统一结构）

```markdown
# 📊 [AI名称] 工作进度汇报

> 时间: 2026-04-10 08:00
> AI: [AI名称]
> OpenID: [OpenID]

## 🔄 本小时完成
1. [任务1] - [状态:✅完成/❌未完成/🔄进行中]
2. [任务2] - [状态]

## 📝 详细记录
- 任务1: [完成情况、产出、遇到的问题]
- 任务2: ...

## 🎯 下小时计划
1. [任务1]
2. [任务2]

## 📚 本小时新增知识资产
- [知识1]: [存放路径]
- [知识2]: [存放路径]

## ⚠️ 风险/阻塞
- [阻塞1]
- [阻塞2]
```

### 汇报存储路径
`SHARED_KNOWLEDGE/工作进度库/日报/YYYY-MM-DD/[AI名称]-HH00.md`

## 四、知识资产写入标准

### 4.1 技能手册写入

当AI学习/开发/部署了新技能，必须写入：

路径: `SHARED_KNOWLEDGE/知识资产库/技能手册/[技能名称].md`

格式:
```markdown
# [技能名称]

> 创建时间: YYYY-MM-DD
> 作者AI: [AI名称]
> AI OpenID: [OpenID]
> 适用场景: [明确说明]
> 熟练度: [掌握/熟悉/了解]
> 来源: [自研/共享池/开源/文档]

## 功能描述
[清晰描述技能能做什么]

## 使用方法
[代码/命令/步骤]

## 案例
```
[实际使用案例]
```

## 注意事项
[坑点、限制、版本要求]

## 相关资源
[链接、依赖]
```

### 4.2 技术方案写入

当AI研究了新方案、开发了新产品，必须写入：

路径: `SHARED_KNOWLEDGE/知识资产库/技术方案/[项目名]-v版本.md`

### 4.3 踩坑记录写入

当AI遇到并解决了问题，必须写入：

路径: `SHARED_KNOWLEDGE/知识资产库/踩坑记录/YYYY-MM-DD-[问题简述].md`

### 4.4 最佳实践写入

当AI发现高效工作方法，必须写入：

路径: `SHARED_KNOWLEDGE/知识资产库/最佳实践/[主题]-[日期].md`

## 五、检索机制

### 5.1 本地快速检索
```bash
# 在共享池中搜索
grep -r "关键词" SHARED_KNOWLEDGE/

# 列出某类所有文档
ls SHARED_KNOWLEDGE/知识资产库/[类别]/

# 查看某AI的所有产出
grep -l "[AI名称]" SHARED_KNOWLEDGE/**/*.md
```

### 5.2 通过飞书搜索
- 文档已同步到飞书云文档（待配置）

### 5.3 索引文件

`SHARED_KNOWLEDGE/INDEX-[YYYY-MM].md`
