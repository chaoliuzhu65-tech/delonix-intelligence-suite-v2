# 多平台龙虾协调架构设计

> 创建：2026-04-09 | 状态：🔍 测试中

## 核心挑战

各龙虾在不同平台（Miaoda/火山引擎/腾讯云/Workbuddy），每个平台：
- 有独立的session管理
- 无法直接调用其他平台的sessions_spawn
- 无法共享内存

**解法：用飞书作为跨平台协调总线**

## 架构设计

```
┌─────────────────────────────────────────────────────────┐
│  妙搭（我，总控师）                                      │
│  - 持有飞书OAuth，读写所有群                            │
│  - 持有多平台龙虾OpenID名单                              │
│  - 分派任务、汇总结果                                    │
└────────────────┬──────────────────────────────────────┘
                 │ 飞书协调消息
                 ↓
┌─────────────────────────────────────────────────────────┐
│  飞书协调总线（oc_36d47ad...）                          │
│  - 妙搭发任务指令                                       │
│  - 各龙虾回执行结果                                      │
│  - 所有龙虾都能读写（租户身份）                          │
└────────────────┬──────────────────────────────────────┘
                 │
     ┌───────────┼───────────┬────────────┐
     ↓           ↓           ↓            ↓
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│ ArkClaw │ │ Qclaw   │ │ 小八    │ │ 腾讯云  │
│(火山引擎)│ │(Qclaw)  │ │(Workbuddy)│ │(腾讯云) │
└────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘
     │           │           │            │
     └──────────┴───────────┴────────────┘
               (各自平台执行任务)

## 消息格式（JSON）

### 妙搭→龙虾：任务分派
{
  "type": "TASK_DISPATCH",
  "task_id": "TASK_001",
  "from": "小柱",
  "to": ["ArkClaw", "小八"],
  "action": "执行预订助手P0",
  "context": "客户：朱辉，2间大床，4/15入住",
  "deadline": "2026-04-09T21:00:00+08:00",
  "reply_to": "oc_36d47ad..."
}

### 龙虾→妙搭：结果回报
{
  "type": "TASK_RESULT",
  "task_id": "TASK_001",
  "from": "ArkClaw",
  "status": "SUCCESS",
  "result": "预订信息已提取，客户档案已匹配",
  "next_action": "等待PMS录入"
}
```

## 当前可用工具

| 工具 | 妙搭→其他龙虾 | 其他龙虾→妙搭 |
|------|--------------|--------------|
| 飞书私信 | ✅ feishu_im_user_message | ❌ 需对方主动发 |
| 飞书群消息 | ✅ 发送 | ✅ 读取（妙搭有OAuth）|
| OpenClaw sessions | ❌ 跨平台不可用 | ❌ |

## 结论

**当前最优方案**：
1. 妙搭通过飞书群发消息给各龙虾
2. 各龙虾执行后，在同一飞书群回复
3. 妙搭读取群消息获取结果

**不需要各龙虾有OAuth** —妙搭的OAuth可以代读所有群消息！
