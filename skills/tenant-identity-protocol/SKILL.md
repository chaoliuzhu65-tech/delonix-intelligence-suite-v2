# 租户身份交互协议 v1.2

> 所有德胧AI龙虾军团成员必须安装的底层协作协议
> 版本：v1.2 | 发布日期：2026-04-14 | 制定者：小柱

---

## 一、协议背景

不同平台的AI伙伴无法用自己的身份代表租户（晁留柱）回复外界，导致协作闭环无法形成。本协议定义三种交互模式，涵盖所有常见协作场景。

---

## 二、三种交互模式

### 模式A：一对一私信交互（最优先）

**场景**：租户与单个AI伙伴之间的私密对话

**规则**：
1. 用 `feishu_im_user_message` 以租户身份发送私信
2. **每条消息必须添加回复要求标记**：`📩 [需回复]`
3. **主动扫描**：发送后定期用 `feishu_im_user_get_messages` 拉取对方回复
4. **扫描策略**：
   - 初始：立即扫描1次
   - 第1次扫描后无回复 → 等30秒再扫
   - 第2次扫描后无回复 → 等60秒再扫
   - 第3次扫描后无回复 → 标记超时，报告租户
5. **回复触发**：收到回复后，立即用租户身份继续交互

**消息格式**：
```
📩 [需回复]
[具体问题/指令]
---
发送者：租户-晁留柱
时间：{当前时间}
```

**终止条件**：
- 对方回复 `【闭环完成】`
- 或连续3次扫描无回复，视为超时放弃
- 或对方给出最终结论/决策

**冗余切换**：如果某AI连续2次超时，自动切换到备选AI伙伴

---

### 模式B：一对多广播交互

**场景**：租户向多个AI伙伴同时发起任务，要求各方独立处理后汇总

**规则**：
1. 用 `feishu_im_user_message` 以租户身份发送广播消息到协作群
2. **必须使用富文本post格式 + XML @标签**：
   ```xml
   <at user_id="ou_xxx">AI名称</at>
   ```
   ⚠️ 注意：必须是XML标签格式，不是JSON格式！

   AI伙伴OpenID对应：
   - `ou_3ccf1eaae932cf5330813ef82cdfba83` → arkclaw版openclaw
   - `ou_8b317f48061dc791c64546264c34db4a` → QclawAI助手
   - `ou_7ffafa7fc8ca551da1bc0c97c186ad89` → 腾讯云Openclaw机器人
   - `ou_51957cbdfd2117fabafcd16c72ff07e6` → LobsterAI
   - `ou_8a2dbf21d13b97d7350295c46de0a62b` → 小妙

3. **每条广播添加汇总要求**：`📢 [需汇总回复]`
4. 各AI伙伴处理完成后，将结果发到协作群，标注 `【待代理-XXX】`
5. **代理发布**：小柱用租户身份将待代理内容转发给目标方

**⚠️ 关键提醒**：
- 富文本post格式 + XML @标签才能激活飞书@通知
- text格式的@只是普通文字，AI不会收到提醒

**@格式验证结果（2026-04-14）**：
| @格式 | 有效性 | 说明 |
|-------|-------|------|
| text格式`@名字` | ❌ | 只是普通文字，不触发通知 |
| JSON `at`标签 | ❌ | API报错 |
| **XML `at`标签** | ✅ | **正确格式！** |

**AI伙伴回复格式**：
```
【待代理-arkclaw代发】
处理结果：[具体内容]
来源：arkclaw版openclaw
```

**终止条件**：
- 所有AI伙伴都回复完毕
- 或超过1小时无新回复
- 或收到 `【汇总完成】`

---

### 模式C：多对多讨论交互

**场景**：多个AI伙伴之间的开放式讨论，协作群内自由发言

**规则**：
1. 讨论在协作群（oc_36d47adad05d3ca8e93164ebc8bfca40）进行
2. **不强制使用租户身份**，各AI伙伴用自己的身份发言
3. **设立"话题主持人"**：由发起讨论的AI担任，负责推动讨论节奏
4. **讨论结果汇报**：讨论完成后，主持人将结论用租户代理协议汇报给租户
5. **禁止无意义刷屏**：有话则长，无话则短

**话题主持人职责**：
- 在讨论开始时声明 `[话题主持-XXX]` 标记
- 总结各方观点，归纳分歧点
- 在适当时机宣布 `[讨论终结]` 并输出结论

**AI伙伴发言格式**：
```
[观点-XXX]
[具体内容]
```

**终止条件**：
- 话题主持人宣布 `[讨论终结]`
- 或30分钟内无新发言
- 或达到最大讨论轮次（10轮）

## 三、核心保障机制

### 3.1 智能扫描机制（不是简单的定时轮询）

```
事件驱动优先：
- 收到新消息 → 立即处理
- 定时兜底（每5分钟检查一次未完成的任务）

扫描策略（见模式A）：
- 指数退避：30秒 → 60秒 → 120秒
- 连续3次无回复 → 标记超时
```

### 3.2 AI伙伴可用性监控

| 状态 | 定义 | 处理 |
|------|------|------|
| 在线 | 30分钟内有过响应 | 正常派发任务 |
| 离线 | 连续2次超时 | 切换到备选AI，记录需检修 |
| 降级 | 回复质量连续不达标 | 降低优先级，重点监控 |

### 3.3 冗余机制

当主AI伙伴离线或质量异常时，自动切换到备选：

```
主AI：arkclaw → 备选：LobsterAI → 备选：QclawAI
主AI：腾讯云Openclaw → 备选：arkclaw
主AI：小妙 → 备选：LobsterAI
```

## 四、回复质量标准

### 4.1 有效 vs 无效回复

| 类型 | 标准 | 示例 |
|------|------|------|
| **有效回复** | 实质性内容 + 可执行信息 | "入住率75%，早餐存量约200份" |
| **无效回复** | 只有表情/"收到"/空泛承诺 | "👍"、"好的"、"收到"、"我在学习中" |

### 4.2 无效回复处理流程

```
收到无效回复 → 记录 [回复质量异常]
     ↓
追问：请提供具体信息
     ↓
连续2次无效回复 → 标记【AI伙伴需检修】
     ↓
报告给租户
```

### 4.3 追问触发条件

| AI回复 | 必须追问 |
|--------|---------|
| "没数据" | "是否有其他途径获取？" |
| "在处理中" | "预计什么时候完成？" |
| "理解了" | "请转达具体执行结果" |
| 只有表情 | "请提供实质内容" |

## 五、通用规则

### 5.1 消息追踪

所有发出的消息必须记录：
- `message_id`
- 发送时间
- 预期回复时间
- 实际回复状态
- 回复质量评分

### 5.2 错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 私信无回复 | 扫描3次后记录超时，切换备选AI |
| 广播无回复 | 记录沉默AI，下次广播时重点@ |
| 讨论偏离主题 | 话题主持人拉回：`[偏离主题，回到正题]` |
| 身份发送失败 | 回退到机器人身份发送，标注 `[降级发送]` |
| AI伙伴离线 | 自动切换备选，标记需检修 |

### 5.3 优先级

```
模式A（一对一） > 模式B（一对多） > 模式C（多对多）
```
