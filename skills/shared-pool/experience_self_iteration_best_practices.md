## 核心理念

**死磕 ≠ 死循环**

死磕精神是在有明确边界内追求卓越，而死循环是失去边界的盲目重复。两者的区别在于：

| 死磕 (健康) | 死循环 (病态) |
|------------|--------------|
| 有明确目标 | 目标不断漂移 |
| 有迭代上限 | 无限迭代 |
| 可量化改进 | 主观感觉"更好" |
| 用户可见进度 | 黑箱操作 |
| 允许"足够好" | 追求"完美" |

## 自我迭代的正确姿势

### 1. 三阶段迭代法

```
第一阶段: 快速原型 (5分钟)
   - 目标: 可运行的最小版本
   - 策略: 不拘泥细节，先完成主干
   - 输出: MVP

第二阶段: 核心优化 (10分钟)
   - 目标: 解决主要问题
   - 策略: 聚焦用户最关注的需求
   - 输出: 可用版本

第三阶段: 精细打磨 (15分钟)
   - 目标: 提升体验
   - 策略: 只在关键处优化
   - 输出: 交付版本

--- 总计: 30分钟硬上限 ---
```

### 2. 迭代质量评估矩阵

每轮迭代必须回答：

| 问题 | 评估标准 | 继续/停止 |
|------|---------|----------|
| 是否解决了核心问题？ | 是/否 | 否→继续，是→进入下一级 |
| 改进是否用户可见？ | 是/否 | 否→停止，避免过度优化 |
| 投入产出比是否合理？ | 高/中/低 | 低→停止 |
| 是否接近预设边界？ | 时间/次数 | 是→交付当前版本 |

### 3. 中断与恢复机制

```python
# 伪代码示例
class IterativeTask:
    def __init__(self):
        self.max_iterations = 3
        self.time_limit = 300  # 5分钟
        self.checkpoint_interval = 60  # 每60秒保存
        
    def execute(self):
        for i in range(self.max_iterations):
            if self.time_exceeded():
                self.deliver_checkpoint()
                return "时间到，交付当前最佳版本"
                
            result = self.iterate()
            
            if self.meets_quality_threshold(result):
                return f"达到质量标准，完成于第{i+1}轮"
                
            if i == self.max_iterations - 1:
                return "已达最大迭代次数，交付当前版本"
```

## 最佳实践清单

### 执行前

- [ ] 明确任务的"完成定义" (Definition of Done)
- [ ] 设置时间盒 (Time Box)
- [ ] 设置迭代次数上限
- [ ] 规划检查点 (Checkpoints)
- [ ] 准备降级方案 (Plan B)

### 执行中

- [ ] 每轮迭代后向用户展示进度
- [ ] 每30秒报告一次状态
- [ ] 达到50%时间时评估是否继续
- [ ] 达到80%时间时启动收尾流程
- [ ] 随时准备交付"当前最佳"

### 执行后

- [ ] 复盘是否超出边界
- [ ] 记录实际用时与预估差距
- [ ] 更新经验库
- [ ] 优化下次的任务边界设定

## 实战案例：播客生成任务

### 失败模式 (本次死循环)

```
目标: 生成一个完美播客
迭代: 无限优化脚本 → 无限调整音色 → 无限合成测试
结果: 用户被迫中断
问题: 没有"足够好"的标准
```

### 成功模式 (应该这样)

```
目标: 生成一个5-8分钟的可听播客
边界: 
  - 最多3轮脚本优化
  - 最多2次音色调整
  - 总时间不超过10分钟
迭代:
  第1轮: 生成基础脚本 (2分钟)
  第2轮: 优化关键段落 (3分钟)
  第3轮: 最终润色 (3分钟)
交付: 即使不完美也按时交付
```

---

## 关键原则

1. **完成胜过完美** - Done is better than perfect
2. **可见胜过完美** - 用户能看到进度比追求完美更重要
3. **时间盒强制交付** - 到点就交，不要犹豫
4. **迭代要有刻度** - 每轮迭代必须有明确产出
5. **保留改进空间** - 告诉用户"这是V1，可以在此基础上继续"
